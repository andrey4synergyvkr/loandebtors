# ADR-004: Advisory lock и идемпотентный запуск

## Контекст

`campaign.start` может быть доставлен повторно, а два consumer могут получить
событие одновременно. Полная выборка АБС и создание сообщений не должны
выполняться дважды.

## Решение

Перед записью результата consumer берет транзакционную advisory-блокировку
кампании `pg_try_advisory_xact_lock`. Если блокировка занята, сообщение
возвращается в retry-очередь. После получения блокировки кампания
перечитывается: если `messages_created_at` уже заполнен, обработка
пропускается. Создание сообщений защищено уникальным ключом идемпотентности.

## Последствия

- Один активный обработчик на кампанию.
- Повторная доставка не создает дублей.
- Занятая блокировка трактуется как временная ошибка.
- Выборка АБС может выполняться параллельно двумя consumer, но запись делает
  только один; это осознанная плата за короткую транзакцию.
