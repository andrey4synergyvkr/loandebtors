# 12. Glossary

Раздел определяет предметные и технические термины, используемые в
документации, чтобы исключить неоднозначность трактовки.

| Термин | Определение |
|--------|-------------|
| АБС | Автоматизированная банковская система, внешний источник истины по должникам, контактным данным и задолженности. |
| Заглушка АБС (`abs`) | Сервис на локальном стенде, который реализует контракт АБС для автономных прогонов и тестов. Не входит в границу Системы. |
| Портфель должников | Набор должников, их контактов и снимков задолженности, полученный из АБС по заданной выборке. |
| Выгрузка (pull) | Постраничный запрос Системы к АБС с нумерацией страниц от 1 до `has_next = false`. Система инициирует запросы, АБС не изменяется. |
| Логический шаблон | Канально-нейтральный шаблон с ключом и версией, общий для всех каналов; текст письма хранится в Email Channel. |
| Версия шаблона | Зафиксированный номер версии логического шаблона, который используется кампанией и сообщением. |
| Снимок должника | Сохраненные в `notification.debtor_snapshots` данные должника на момент полной выгрузки кампании. |
| Сообщение | Запись в `notification.messages`, созданная для должника и канала в рамках кампании. |
| Попытка отправки | Запись в `notification.message_attempts` с номером попытки, результатом и временем ответа провайдера. |
| Идемпотентный ключ | Ключ `campaign_id:debtor_id:channel`, который защищает от создания двух сообщений для одной тройки. |
| Outbox | Транзакционная таблица `notification.outbox` для надежной публикации событий и команд после фиксации состояния. |
| Outbox relay | Фоновый процесс, который выбирает готовые записи outbox и публикует их в RabbitMQ с publisher confirms. |
| Unit of Work | Граница транзакции, объединяющая репозитории, outbox и audit-события одного сценария. |
| Advisory lock | Транзакционная блокировка PostgreSQL, которая не дает двум consumer одновременно обрабатывать одну кампанию. |
| Retry | Повторная обработка временно неуспешного шага через retry-очередь RabbitMQ или отложенную запись outbox. |
| DLQ | Dead-letter очередь для сообщений, которые не удалось обработать после исчерпания повторов или из-за ошибки валидации. |
| Consumer | Компонент сервиса, который принимает сообщения очереди, вызывает сценарий приложения и подтверждает или отклоняет сообщение. |
| Recovery | Фоновое восстановление зависших кампаний и сообщений после сбоя процесса или потери сообщения. |
| Retention | Политика удаления старых опубликованных записей outbox и попыток отправки. |
| Кампания | Агрегат с именем, шаблоном, выборкой должников, расписанием и статусом жизненного цикла. |
| Получатель (Recipient) | Адрес доставки в формате канала, например email-адрес должника. |
